# 그래픽 리소스 규격 — 「스테인드글라스 실루엣」

이 문서 하나로 그림을 발주하거나 직접 그려 넣을 수 있게 쓴 것이다.
**코드는 이미 준비돼 있다.** 규격대로 시트를 만들어 물리면 게임 코드는 한 줄도 안 바뀐다.

레퍼런스 아틀라스가 `art/reference-atlas.png` 에 들어 있다. 최종 아트가 아니라
**자리 표시자 겸 기준자**다 — 같은 칸에 같은 크기로 덮어 그리면 그대로 교체된다.

---

## 1. 왜 이 스타일인가

화면에 적이 **최대 340마리**까지 뜬다. 디테일이 많은 도트나 반실사는 그 밀도에서
뭉개진다. 실제로 이 프로젝트에서 반복해서 부딪힌 제약은 항상 "밀도"였다 —
몬스터 이름표도 겹침 때문에 표시 개수를 26개로 제한해야 했다.

그래서 **실루엣과 색 대비만 남기는** 스타일을 택한다. 성당 스테인드글라스가
정확히 그 구조다: 굵은 납선(윤곽) + 투과광(발광색). 템플러 컨셉과도 맞고,
신성·화염·냉기·뇌전 속성이 그대로 유리색이 된다.

## 2. 스타일 규칙 4개

| | 규칙 |
| --- | --- |
| **윤곽** | 모든 유닛에 굵은 검은 윤곽(`#0a0a12`). 프레임 크기의 **10~16%** 두께. 배경과 무조건 분리된다 |
| **색** | 유닛당 **주색 1 + 발광색 1**. 세 번째 색은 쓰지 않는다 |
| **발광** | 위험한 것만 빛난다 — 보스, 정예, 예고 범위, 수정 기둥, 화톳불 |
| **배경** | 채도를 유닛의 절반 이하로. 지형은 어둡게 깔리고 적만 뜬다 |

주색은 게임 데이터의 `ENEMY_TYPES[*].color` 를 그대로 쓴다. 색을 새로 정하지 말 것 —
미니맵·피격 파티클·체력바가 전부 같은 값을 참조한다.

## 3. 프레임 크기 — 이 계산이 규격의 핵심이다

호출부는 `Sprites.draw(key, sx, sy, 적반지름 / 14, ...)` 로 그린다. 즉

```
화면에 그려지는 폭 = 프레임 폭 w × (적 반지름 r / 14) × (프레임의 s, 기본 1)
```

히트박스 지름은 `2r` 이므로, **그림이 히트박스와 정확히 겹치려면 `w × s = 28`** 이어야 한다.

| 프레임 | `s` | 결과 |
| --- | --- | --- |
| 28 × 28 | 1 | 히트박스와 정확히 일치 |
| **32 × 32** | 1 | 1.14배 — 살짝 넘치게 그려져 보기 좋다. **일반 몬스터 기본값** |
| **64 × 64** | **0.438** | 화면 크기는 32px 짜리와 같고 **픽셀 밀도만 2배**. **보스 기본값** |

보스는 반지름이 42~50 이라 32px 프레임을 3배 이상 확대하게 되어 뭉개진다.
그래서 큰 프레임을 쓰고 `s` 로 되돌린다.

`ox` / `oy` 로 기준점을 옮길 수 있다(기둥처럼 위로 긴 그림을 발밑에 맞출 때).

## 4. 시트 배치

```
가로 = 프레임 폭 × 프레임 수      (애니메이션은 가로로 나열)
세로 = 종류마다 한 줄씩 아래로
```

- 애니메이션 **4프레임**, 기본 **8fps**. 빠른 것(박쥐·사냥개)만 10fps
- 여백·패딩 없음. 프레임은 정확히 맞닿는다
- 배경 투명 PNG. 보간이 꺼져 있으므로(`imageSmoothingEnabled = false`) 반투명 가장자리는 지저분해진다 — **안티에일리어싱 없이** 그릴 것
- 좌우 반전은 코드가 처리한다(`flip`). **오른쪽을 보는 그림만** 그리면 된다

## 5. 그려야 하는 것 — 17종, 그러나 실루엣은 6종

`ENEMY_TYPES[*].shape` 가 이미 6종으로 묶여 있다. **17장을 새로 그리지 말고
실루엣 6종을 그린 뒤 색만 바꾸는 것**을 권한다.

| 실루엣 | 쓰는 몬스터 |
| --- | --- |
| `bat` | 박쥐 |
| `blob` | 슬라임 · 분열체 · 폭발체 |
| `ghost` | 유령 · 사신 · 주술사 |
| `humanoid` | 좀비 · 괴수 · 사수 · 돌진자 · 방패병 |
| `hound` | 사냥개 |
| `boss` | 제단의 파수꾼 · 역병 군주 · 강철 처형자 · 심연의 왕 |

**등급(정예·희귀)은 추가 그림이 필요 없다.** 코드가 테두리와 크기(×1.24 / ×1.5)로
구분하고 이름표를 붙인다.

## 6. 물리는 법

```js
Sprites.load("atlas.png", {
  bat:   { x: 0, y:   0, w: 32, h: 32, n: 4, fps: 10 },
  slime: { x: 0, y:  32, w: 32, h: 32, n: 4, fps: 8  },
  // ...
  boss1: { x: 0, y: 480, w: 64, h: 64, n: 4, fps: 8, s: 0.438 },
});
```

`art/atlas-frames.json` 이 레퍼런스 아틀라스에 맞는 프레임 정의다. 그대로 붙여 쓰면 된다.

**로드에 실패해도 게임은 그대로 돈다** — `Sprites.draw` 가 `false` 를 돌려주면
호출부가 도형 렌더링으로 폴백한다. 그래서 아트를 한 종류씩 넣어도 되고,
넣다 만 상태로 배포해도 깨지지 않는다.

> 현재 배포본은 **도형 렌더링**을 쓴다. 아티팩트는 외부 파일을 실을 수 없어서,
> 아틀라스를 켜면 아티팩트와 GitHub Pages 가 서로 달라 보이기 때문이다.
> 전면 교체할 때 `Sprites.load` 한 줄을 켜면 된다(PNG 를 data URI 로 넣으면 아티팩트에서도 된다).

## 7. 조달 순서 — 비용 대비 효과 순

1. **실루엣 6종**을 먼저 확보한다. itch.io 의 CC0 실루엣 팩으로 시작해도 된다
2. 반응이 오면 **보스 3종 + 직업 4종**만 전용 아트로 교체한다. 화면에서 가장 오래 보이고
   가장 크게 보이는 것들이다
3. 지형 12종은 **가장 나중**이다. 지금 도형으로도 종류가 구분되고, 크기 편차가
   이미 이정표 역할을 한다

## 8. 레퍼런스 아틀라스 다시 만들기

```sh
node art/make-atlas.js     # art/reference-atlas.png 와 atlas-frames.json 을 다시 뽑는다
```

몬스터를 추가하면 `art/atlas-spec.json` 에 한 줄만 넣으면 된다.
색과 실루엣은 게임 데이터에서 그대로 가져오므로 어긋날 일이 없다.

## 9. 주인공 — 직업 4종 × 동작 4종

몬스터는 단색 실루엣이지만 주인공은 그럴 수 없다. 화면 가운데에서 가장 오래 보이는 것이
한 덩어리 색이면 무엇을 들고 있는지, 지금 무엇을 하고 있는지 읽히지 않는다.
그래서 주인공만 팔레트를 늘렸다.

| 글자 | 쓰임 |
|---|---|
| `A` / `a` | 직업색과 그 그늘 (망토·문양·로브) |
| `S` / `s` | 살 · 살 그늘 |
| `M` / `m` | 강철 · 강철 그늘 |
| `L` / `l` | 가죽 · 가죽 그늘 |
| `W` | 날 끝 광택 · 영창의 빛 |

동작 4종과 각 지속시간(`ACT_DUR` · `CAST_DUR` 은 프레임 4장 ÷ fps 라서 정확히 한 바퀴만 돈다):

| 동작 | fps | 언제 |
|---|---|---|
| `idle` | 6 | 멈춰 있을 때 |
| `walk` | 10 | `player.moving` |
| `attack` | 14 | 무기가 나갈 때(`player.actT`) · 돌진 중 |
| `cast` | 12 | 직업 스킬을 쓸 때(`player.castT`) |

키는 `hero_<직업키>_<동작>` 이다. 오른쪽을 보게만 그리고 왼쪽은 `player.flip` 으로 뒤집는다.
`player.faceX` 는 조준에도 쓰이므로 반전 판정에 쓰지 않는다 — 세로로만 움직이면 0 이 된다.

읽히게 만들려고 실패한 것들:

* 망토를 몸 폭만큼 넓히면 **치마**가 된다 → 왼쪽 뒤로만, 다리는 덮지 않는다
* 무기를 1~2px 로 얇게 그리면 게임 크기에서 **사라진다** → 굵게, 끝에 흰 광택
* 광택을 날 전체에 그으면 날이 **두 배로 두꺼워** 보인다 → 끝 2px 만
* 영창에 두 팔을 올리면 **살색 덩어리**가 된다 → 한 팔만 들고 빛은 무기 앞 한 점에 모은다
* 도끼·지팡이를 수평으로 들면 **걸레·빗자루**다 → 직업별 평상시 각도를 따로 둔다
* `outline()` 은 겉만 잡는다. 허리·다리 사이·투구 틈은 **직접 검은 선**을 그어야 형태가 갈린다

## 10. 이펙트 — 4종 × 속성 6종

타격·폭발·베기·시전이 전부 원과 `shadowBlur` 뿌연 광원이었다. 몬스터와 주인공을
픽셀로 바꾸고 나니 이펙트만 재질이 달라 겉돌았다. 같은 방식으로 픽셀로 찍는다.

| 종류 | 크기 | fps | 언제 |
|---|---|---|---|
| `fx_hit_*` | 32 | 22 | 적이 맞을 때 |
| `fx_boom_*` | 48 | 13 | 처치 · 파동(폭발) · 낙뢰 |
| `fx_slash_*` | 48 | 17 | 근접 베기 (호출부가 각도로 회전) |
| `fx_cast_*` | 32 | 20 | 무기가 나갈 때 |

키는 `fx_<종류>_<속성>` 이고 속성은 물리·화염·냉기·뇌전·신성·피 6종이다.
없는 속성은 `fxKey()` 가 물리로 떨어뜨린다.

이펙트는 몬스터·주인공과 규칙이 다르다.

* **검은 윤곽을 두르지 않는다.** 빛이기 때문이다 — 각 실루엣이 `outline()` 을 부르지 않는다
* **`s`(축소 배수)를 넣지 않는다.** 프레임 크기가 종류마다 달라, `spawnFx` 가
  화면 픽셀 크기를 직접 받고 `px / fr.w` 로 배수를 계산한다. 스펙의 `fx: true` 가 그 표시다
* **색이 `ELEMENTS` 와 다르다.** 가산 합성으로 그리므로 물리(`#d8d8e4`)·신성(`#ffd9a0`) 을
  그대로 쓰면 어두운 배경 위에서 흰 덩어리가 된다. 이펙트에만 채도를 올린 값을 쓴다
  (`#93a6c4` · `#ffc266`). UI·미니맵 색은 건드리지 않는다

혼잡할 때 스스로 줄어든다:

* 적 하나당 `e.flash` 가 남아 있으면 타격 이펙트를 건너뛴다 — 0.12초에 한 번
* 살아 있는 이펙트가 70개를 넘으면 새 타격 이펙트를 포기한다(`fxLive`).
  200마리를 한꺼번에 때리면 불꽃이 서로를 밀어내 죄다 중간에 잘리고 뿌연 덩어리가 된다.
  그럴 바엔 안 그리는 편이 낫다. 치명타만 예외로 항상 그린다
* 배열을 훑어 세면 초당 천 번씩 도는 셈이라 `fxLive` 를 증감으로 관리한다

그리기는 **가산 합성을 루프 바깥에서 한 번만 켠다**. 이펙트마다 `globalCompositeOperation`
을 갈아 끼웠더니 그 전환만으로 프레임이 눈에 띄게 느려졌다.

## 11. 큰 이펙트 — 스프라이트로는 못 그린다

지난 절에서 베기를 `fx_slash` 스프라이트로 그렸다. 그게 틀렸다.

`Sprites.draw` 는 프레임을 확대해서 그린다. 베기의 사거리는 무기마다 다르다 —
쇠사슬 플레일 92, 8레벨 268, 심판의 빛 **520**. 48px 한 장을 520 에 맞추면
**25배 확대**다. 실제로 그렇게 배포했고 화면 1/3을 덮는 계단 모양 덩어리가 나왔다.

기준은 이렇다. **주변 스프라이트가 1:1 로 그려지는데 혼자 몇 배로 확대되면
같은 화면의 픽셀 크기가 어긋난다.** 3배가 한계다.

그래서 큰 이펙트는 화면 픽셀 격자(`PIX = 3`)에 맞춰 직접 찍는다.
길이가 92든 520이든 눈에 보이는 픽셀 크기가 같다.

| 함수 | 쓰는 곳 |
|---|---|
| `pxArc` | 베기 (사거리 300 이하) — 휘두르는 초승달 |
| `pxLance` | 베기 (사거리 300 초과) — 앞으로 내지르는 빛의 창 |
| `pxRing` | 파동 — 퍼져 나가는 고리 |
| (인라인) | 낙뢰 — 꺾인 점 사이를 격자 칸으로 |

`spawnSlash` 에 종류를 따로 두지 않고 **사거리로 갈린다**. 300 을 넘는 베기는
전부 '앞으로 길게 뻗는' 스킬이고, 그걸 부채꼴로 그리면 화면을 덮기 때문이다.

### 두 번 크게 틀렸다

**① 순백을 심지로 썼다.** 이펙트는 가산 합성으로 그린다. `[흰색, 중간, 속성색]`
으로 깔았더니 화염·냉기·신성 파동이 **전부 회색 고리**로 나왔다. 흰색이 겹치는
순간 색이 날아간다. 게다가 물리(`#d8d8e4`)·신성(`#ffd9a0`)은 이미 밝아서
더 밝힐 데도 없다. 그래서 `pxPal` 이 밝기를 보고 갈린다 —
어두운 색은 밝혀서 겉을 만들고, 밝은 색은 **원색을 몸통으로 두고 아래로 깐다**.

**② 칸마다 `fillStyle` 을 갈고 `fillRect` 를 불렀다.** 최악의 프레임에서
**5.8 → 30ms**. 칠할 색은 세 가지뿐이므로 좌표만 쌓아 두었다가 색당 한 번씩
`path` 로 칠한다(`pxPush` / `pxFlush`). 30 → 7.9ms 로 돌아왔다.

계측(적 200 + 긴 베기 3 + 파동 2 + 낙뢰 3 이 매 프레임 살아 있는 인위적 최악):
이전 4.5~7.8ms · 현재 7.3~8.7ms. 일반 전투(적 200, 이펙트 폭주 없음)는
2.2~2.8 vs 2.6~3.4ms 로 겹친다.

## 12. 발사체 — 스프라이트를 쓸 수 없는 이유

발사체는 반지름 5~45 라 스프라이트를 써도 3배 이내다. 규격상으로는 가능하다.
그런데 못 쓴다 — **무기마다 색이 제각각이기 때문이다.**
`spawnProjectile` 이 받는 `color` 는 속성이 아니라 무기별 값이라, 아틀라스에
색깔 수만큼 줄을 넣을 수는 없다. 그래서 여기도 격자로 찍는다.

`pxDisc` 는 **원을 그린 뒤 테두리에 칸을 덧찍지 않는다.** 가로줄로 직접 찍는다 —
안쪽까지 전부 격자에 맞아 진짜 픽셀 원이 되고, 테두리를 따로 도는 비용도 없다.
(테두리를 덧찍는 방식으로 먼저 만들었다가 탄 200발에서 7.6~9.9 → 11.4~11.8ms 로
느려졌다. 가로줄 방식으로 바꾸니 8.2~10.6ms 로 겹친다.)

| 종류 | 그리는 법 |
|---|---|
| 구체 · 불꽃 | `pxDisc` — 겉/속 두 겹. 불꽃은 날아가며 사그라든다 |
| 단검 | 꼭짓점을 직접 돌려 채우고 `pxEdge` 로 테두리 |
| 적 탄 | 붉은 `pxDisc` 위에 제 색 `pxDisc` — 아군 탄과 절대 헷갈리면 안 된다 |

단검만 회전이 필요한데, **회전된 좌표계에서 칸을 찍으면 안 된다.**
격자는 화면 좌표 기준이라 변환 아래에서는 어긋나고 안티에일리어싱이 되돌아온다.
꼭짓점 세 개를 직접 돌려 화면 좌표로 만든 다음 찍는다.

## 13. 바닥 장판

장판은 '점'이 아니라 '면'이다. 발사체처럼 꽉 찬 원으로 그리면 웅덩이가 아니라
색칠한 바닥이 된다. 그래서 셋으로 나눈다.

* **속** — 가로줄로 찍은 옅은 원. 발밑이 어디까지 위험한지 면으로 보인다
* **테두리** — 격자 칸을 **한 칸씩 띄운 점선**. 촘촘히 두르면 장판 하나당 200칸이라
  오래 남는 효과치고 비싸고(장판 6개에 +1.6ms), 점선이 오히려 '여기까지가 구역'으로
  더 잘 읽힌다. 띄우니 +0.6ms 로 내려갔다
* **방울** — 저마다 다른 주기로 떴다 사라지는 칸 16개. 평평한 원에 생기를 준다.
  위치는 `hash2` 로 뽑아 프레임마다 흔들리지 않는다

### 정리 — 무엇을 무엇으로 그리는가

| 크기 | 방법 | 예 |
|---|---|---|
| 고정 크기, 색이 유한 | **스프라이트** (1:1~3배) | 몬스터 · 주인공 · 타격/폭발/시전 |
| 크기가 변하거나 색이 자유 | **격자 렌더** | 베기 · 파동 · 낙뢰 · 발사체 · 장판 · 성역 |

기준은 하나다. **주변 스프라이트가 1:1 인데 혼자 몇 배로 확대되면 어긋난다.**

## 14. 대형 구조물

지형지물(상자·제단·비석)은 한 번 만지고 끝나는 '점'이다.
구조물은 '장소'다 — 켜 두고 그 자리를 지켜야 값을 한다.
크기도 다르다. 반지름 110~180 으로 기존 지형의 두 배 이상이다(폐허가 40~96).

크기가 종류마다 다르고 켜짐/꺼짐으로 색이 바뀌므로 **격자 렌더**다(12·13절의 규칙).

멀리서 실루엣이 구분되어야 갈지 말지를 정할 수 있다. 그래서 윗부분의 형태를 다르게 한다 —
첨탑은 뾰족하게, 샘은 낮고 둥글게, 성채는 톱니, 대장간은 굴뚝.
꺼져 있을 때도 종류색을 조금 섞는다. 전부 같은 회색이면 멀리서 무엇인지 모른다.

큰 면이 비어 있으면 건물이 아니라 판자로 보인다. 그래서 어두운 구멍을 판다 —
첨탑의 띠, 샘의 기둥 사이 그늘, 성채의 화살 구멍과 성문, 대장간의 입구.
