## 2. 아키텍처

### 2.1 Mock-First 설계

백엔드가 아직 없는 상태에서, **나중에 서버를 붙일 때 UI를 고치지 않아도 되도록** 계층을 분리했습니다.

```
src/
├── pages/          라우트별 화면 (교사 5 + 공급업체 3)
├── components/     레이아웃 · 도메인별 UI 컴포넌트
├── api/            데이터 레이어 (Mock) ← 백엔드 전환 시 이 폴더만 교체
├── lib/            순수 로직 (계산·매칭·문서 생성) ← 단위 테스트 대상
├── store/          Zustand 전역 상태
└── config/         역할별 네비게이션 정의
```

- `api/` 모듈은 **스펙의 API 응답 형태를 그대로 반환**합니다. 서버 도입 시 함수 본문만
  `fetch` 호출로 바꾸면 됩니다. 각 파일 상단에 전환 지점(엔드포인트, Prisma 스키마,
  임베딩 모델)을 주석으로 명시했습니다.
- 데이터 영속화는 `localStorage`를 사용하며, 저장 키와 레코드 구조도 DB 스키마를 반영합니다.
- `lib/`은 DOM·네트워크에 의존하지 않는 순수 함수로만 구성해, 계산 로직을 빠르게 검증합니다.

### 2.2 역할 기반 라우팅

| 역할 | 경로 |
| --- | --- |
| 교사/원장 | `/teacher/dashboard`, `/teacher/plan`, `/teacher/quotes`, `/teacher/journal`, `/teacher/deliberation` |
| 공급업체 | `/supplier/dashboard`, `/supplier/products`, `/supplier/orders` |

루트(`/`)와 미정의 경로는 현재 역할의 대시보드로 리다이렉트되고, 현재 역할이 접근할 수 없는
영역의 URL도 해당 역할의 대시보드로 되돌립니다. 헤더의 역할 전환 버튼으로 두 화면군을 오갑니다.

## 3. 구현 기능

### 3.1 교사/원장

#### ① 메인 대시보드 (`/teacher/dashboard`)
- 요약 카드 3종: 이번 달 생성한 교육계획안, 진행 중인 견적서, AI 매칭 교재·교구
- 최근 활동 타임라인, 빠른 실행 버튼
- 누리과정 가이드 위젯

#### ② AI 교육계획안 수립 (`/teacher/plan`)
- **주간 / 월간 / 연간** 3가지 계획 유형, 누리과정 **5대 영역**(신체운동·건강, 의사소통,
  사회관계, 예술경험, 자연탐구) 기반 표 생성
- 연령별(만 3·4·5세) 맞춤 주제·활동 목표·준비물 차등 생성 (`lib/ageProfiles.ts`)
- **셀 더블클릭 인라인 편집** — 활동명·설명·목표를 직접 수정
- 미저장 변경 이탈 방지 (SPA 라우팅 차단 + `beforeunload` 경고)
- 생성 요청 15초 타임아웃 + 실패 시 재시도 UI
- 계획안 저장·열기·삭제 (localStorage)
- **계획안 PDF 다운로드** — 추천 교재 견적 요약 포함, 페이지네이션 처리
  (파일명 규칙: `{YYYYMMDD}_{기관명}_교육계획안_견적서.pdf`)

#### ③ 교재 추천 및 견적서 (`/teacher/quotes`)
- 계획안 활동 키워드 ↔ 교구 메타데이터 **시맨틱 매칭**으로 교재 자동 추천
- 추천 교재 **상세 카드 뷰**: 이미지, 단가, 적정 연령, 누리과정 연계 영역, 교육 효과
- **대체 교재 선택** 및 추천 리스트 커스텀 조정(선택 해제, 교체, 행 삭제)
- 인원수·예산 입력 시 **실시간 견적 금액 자동 산출** (개인별/공용 품목 구분)
- 예산 초과·미달 경고 표시
- 견적 확정 후 **PDF / Excel 다운로드** (Excel은 수식·서식 포함)

#### ④ 보육일지 및 평가 (`/teacher/journal`)
- 날짜 선택 → 해당 날짜가 속한 계획안 기간의 활동을 자동 매핑
  (주간: 요일 / 월간: 최대 4주 / 연간: N월)
- 계획안에 **근거한** 일과표·활동 평가 초안 생성 (계획에 없는 교구를 지어내지 않음)
- 모든 항목 인라인 편집, 날짜별 저장
- 담임·원감·원장 **결재란**이 포함된 PDF 내보내기

#### ⑤ 운영위원회 심의서 (`/teacher/deliberation`)
- 견적서에서 "운영위원회 심의서 생성" 버튼으로 진입
- 4개 섹션 자동 작성: **도입 목적 / 누리과정 연계성 / 예산 대비 타당성 / 기대 효과**
- 심의 대상 교구 목록, 수량 조정, 총 소요 금액·예산 소진율 자동 계산
- PDF / Excel 내보내기

> **금액 무결성**: 심의서의 총액·소진율은 AI 문장이 아니라 **코드에서 계산한 값**을
> 주입합니다. 생성 문구에 금액을 맡기지 않아 숫자 오류가 원천 차단됩니다.

### 3.2 공급업체

#### ⑥ 공급업체 대시보드 (`/supplier/dashboard`)
- 신규 주문·처리 대기 건수, 매출 요약
- 상태별 주문 현황과 최근 주문 목록

#### ⑦ 교재·교구 관리 (`/supplier/products`)
- 상품 등록·수정·삭제 (단가, 적정 연령, 카테고리, 키워드, 누리과정 영역)
- **엑셀 일괄 업로드** — 템플릿 다운로드, 형식 검증, 오류 행 리포트, 신규/갱신 판별
- AI 추천 색인 동기화 상태(`ragSynced`) 표시

#### ⑧ 주문 및 견적 확인 (`/supplier/orders`)
- 6단계 상태 관리: 대기 → 견적확인 → 발주완료 → 배송중 → 완료 / 취소
- 주문 상세 모달에서 상태 변경·운송장 번호 입력
- 주문 내역 Excel 다운로드
- 교사 화면에서 발생한 주문이 공급업체 목록에 **실시간 반영**
  (폴링 + `storage` 이벤트로 브라우저 탭 간 동기화)

## 4. 핵심 기술 구현

### 4.1 RAG 스타일 시맨틱 매칭 (`lib/similarity.ts`, `lib/conceptMap.ts`)

임베딩 서버 없이 브라우저에서 동작하는 경량 매칭 엔진입니다.

1. **토크나이즈** — 한국어 특성을 고려해 어절 + 문자 바이그램을 함께 추출
2. **TF 코사인 유사도** — 활동 설명과 상품 메타데이터 간 어휘 유사도 산출
3. **개념 사전 브리지** — "물감/색칠" ↔ "미술 재료"처럼 **표현은 다르지만 같은 개념**인
   쌍을 사전으로 연결해, 어휘가 겹치지 않아도 매칭
4. **신뢰도 보정** — `min(0.99, 0.7 + min(브리지수-1, 2)×0.03 + 어휘유사도×0.35)`
   → 개념으로만 연결된 결과가 **직접 어휘 일치 결과를 앞서지 않도록** 가중치를 조정
5. **연령 필터** — 상품의 적정 연령 범위와 계획안 대상 연령이 겹치는 항목만 통과
6. **대체 추천 통합** — 여러 활동에서 나온 대체안을 최고 점수 기준으로 병합·중복 제거

> **환각 차단**: 추천 결과는 **등록된 카탈로그 안의 상품만** 반환합니다. 존재하지 않는
> 교구가 제안될 수 없는 구조입니다. (현재 카탈로그 13종)

### 4.2 견적 계산 엔진 (`lib/quotation.ts`, `lib/estimate.ts`)

- **개인별 품목**(`isPerStudent`)은 인원수 변경 시 수량이 자동 연동, 공용 품목은 고정
- 사용자가 수량을 직접 수정하면 `isManuallyEdited` 플래그로 **자동 연동에서 제외**
- 단가는 **항상 카탈로그에서 조회** — 화면 값을 신뢰하지 않아 조작 여지 차단
- 수량 하한(0 / 1) 보정, 잘못된 입력 정규화
- 교재·도서류 면세 처리(`taxRate: 0`) 반영

### 4.3 문서 생성 (PDF / Excel)

- **한글 PDF**: NanumGothic TTF를 번들 에셋으로 포함하고 fontkit으로 **서브셋 임베딩** →
  서버리스·컨테이너 환경에서도 폰트 설치 없이 동작하며 결과 파일이 가볍습니다.
  (구글 폰트 CDN이 제공하는 sliced TTF는 fontkit 파싱이 실패해, 공식 저장소 원본 TTF 사용)
- **지연 로드**: PDF·Excel 엔진은 다운로드 버튼을 눌러야 로드되어 초기 진입 속도에 영향 없음
- 문서 5종: 견적서 PDF/Excel, 교육계획안 PDF, 보육일지 PDF, 심의서 PDF/Excel, 주문내역 Excel

### 4.4 안정성 경화

- **전역 Error Boundary + 라우터 `errorElement`** — 렌더링 크래시가 흰 화면이 되지 않고
  복구 안내 UI로 전환되며, 세션 데이터(localStorage)는 유지한 채 홈에서 재시작
- `lib/monitoring.ts` — window 전역 에러·미처리 Promise 거부 수집 (Sentry 도입 시 내부만 교체)
- `public/maintenance.html` — 배포·점검 시 라우팅할 정적 점검 페이지
- 반응형: 375px 모바일에서 가로 스크롤 없이 동작(넓은 표는 내부 스크롤), 모바일 드로어 네비게이션

- 보육일지·심의서 생성 및 문서 출력
- 크래시 복구, 라우트 에러, 모바일 반응형, 콘솔 에러 없음

## 6. 라이브 프리뷰

백엔드 없이 동작하는 구조를 활용해, 전체 앱을 **단일 HTML 파일**로 빌드해 공유합니다.

```bash
ARTIFACT_BUILD=1 npm run build   # dist-artifact/ (해시 라우터 + 에셋 인라인)
```

프리뷰 환경(샌드박스 iframe)의 제약과 대응:

| 제약 | 대응 |
| --- | --- |
| 파일 다운로드 차단 | `lib/exportGate.ts`로 내보내기 진입점을 차단하고 안내 문구 표시. 부수 효과로 PDF/Excel 엔진과 폰트가 번들에서 제거되어 **5.1MB → 849KB** |
| `window.confirm` 무력화 (항상 취소 처리) | 프리뷰 빌드에서는 확인 절차를 생략하는 `confirmAction`으로 대체. 이 문제로 계획안 생성 후 **모든 메뉴 이동이 막히던 버그**를 해결 |
| 해시 라우터에서 `/` 이동 시 앱 이탈 | 오류 복구 이동을 해시 초기화 + 새로고침으로 대체 |

> 위 우회는 **프리뷰 빌드에서만** 적용되며, 실제 배포 빌드에서는 빌드 상수가 `false`로
> 접혀 분기 자체가 제거됩니다. 동작 차이가 없습니다.

## 7. 백엔드 전환 체크리스트

## 10. 알려진 제약 및 향후 과제

- **인증 없음** — 역할 전환은 헤더 버튼으로 동작하는 Mock입니다. 실제 로그인·권한 검사가 필요합니다.
- **AI 생성은 규칙 기반 Mock** — 계획안·일지·심의서 문장은 연령/주제/활동에 따라 조합되는
  결정적 로직입니다. 실제 LLM 연동 시 프롬프트와 응답 스키마 설계가 필요합니다.
- **데이터는 브라우저 로컬 저장** — 기기·브라우저 간 공유가 되지 않습니다. DB 도입이 전제입니다.
- **결제·정산 미구현** — 주문은 상태 관리까지만 다룹니다.
- 향후: 계획안 버전 관리, 원아별 관찰 기록, 공급업체 다중 입점, 알림(메일/카카오) 연동
