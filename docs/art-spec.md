# 그래픽 리소스 규격 — 「스테인드글라스 실루엣」

이 문서 하나로 그림을 발주하거나 직접 그려 넣을 수 있게 쓴 것이다.
**코드는 이미 준비돼 있다.** 규격대로 시트를 만들어 물리면 게임 코드는 한 줄도 안 바뀐다.

레퍼런스 아틀라스가 `art/reference-atlas.png` 에 들어 있다. 최종 아트가 아니라
**자리 표시자 겸 기준자**다 — 같은 칸에 같은 크기로 덮어 그리면 그대로 교체된다.

---

## 1. 왜 이 스타일인가

화면에 적이 **최대 340마리**까지 뜬다. 디테일이 많은 도트나 반실사는 그 밀도에서
뭉개진다. 실제로 이 프로젝트에서 반복해서 부딪힌 제약은 항상 "밀도"였다 —
몬스터 이름표도 겹침 때문에 표시 개수를 26개로 제한해야 했다.

그래서 **실루엣과 색 대비만 남기는** 스타일을 택한다. 성당 스테인드글라스가
정확히 그 구조다: 굵은 납선(윤곽) + 투과광(발광색). 템플러 컨셉과도 맞고,
신성·화염·냉기·뇌전 속성이 그대로 유리색이 된다.

## 2. 스타일 규칙 4개

| | 규칙 |
| --- | --- |
| **윤곽** | 모든 유닛에 굵은 검은 윤곽(`#0a0a12`). 프레임 크기의 **10~16%** 두께. 배경과 무조건 분리된다 |
| **색** | 유닛당 **주색 1 + 발광색 1**. 세 번째 색은 쓰지 않는다 |
| **발광** | 위험한 것만 빛난다 — 보스, 정예, 예고 범위, 수정 기둥, 화톳불 |
| **배경** | 채도를 유닛의 절반 이하로. 지형은 어둡게 깔리고 적만 뜬다 |

주색은 게임 데이터의 `ENEMY_TYPES[*].color` 를 그대로 쓴다. 색을 새로 정하지 말 것 —
미니맵·피격 파티클·체력바가 전부 같은 값을 참조한다.

## 3. 프레임 크기 — 이 계산이 규격의 핵심이다

호출부는 `Sprites.draw(key, sx, sy, 적반지름 / 14, ...)` 로 그린다. 즉

```
화면에 그려지는 폭 = 프레임 폭 w × (적 반지름 r / 14) × (프레임의 s, 기본 1)
```

히트박스 지름은 `2r` 이므로, **그림이 히트박스와 정확히 겹치려면 `w × s = 28`** 이어야 한다.

| 프레임 | `s` | 결과 |
| --- | --- | --- |
| 28 × 28 | 1 | 히트박스와 정확히 일치 |
| **32 × 32** | 1 | 1.14배 — 살짝 넘치게 그려져 보기 좋다. **일반 몬스터 기본값** |
| **64 × 64** | **0.438** | 화면 크기는 32px 짜리와 같고 **픽셀 밀도만 2배**. **보스 기본값** |

보스는 반지름이 42~50 이라 32px 프레임을 3배 이상 확대하게 되어 뭉개진다.
그래서 큰 프레임을 쓰고 `s` 로 되돌린다.

`ox` / `oy` 로 기준점을 옮길 수 있다(기둥처럼 위로 긴 그림을 발밑에 맞출 때).

## 4. 시트 배치

```
가로 = 프레임 폭 × 프레임 수      (애니메이션은 가로로 나열)
세로 = 종류마다 한 줄씩 아래로
```

- 애니메이션 **4프레임**, 기본 **8fps**. 빠른 것(박쥐·사냥개)만 10fps
- 여백·패딩 없음. 프레임은 정확히 맞닿는다
- 배경 투명 PNG. 보간이 꺼져 있으므로(`imageSmoothingEnabled = false`) 반투명 가장자리는 지저분해진다 — **안티에일리어싱 없이** 그릴 것
- 좌우 반전은 코드가 처리한다(`flip`). **오른쪽을 보는 그림만** 그리면 된다

## 5. 그려야 하는 것 — 17종, 그러나 실루엣은 6종

`ENEMY_TYPES[*].shape` 가 이미 6종으로 묶여 있다. **17장을 새로 그리지 말고
실루엣 6종을 그린 뒤 색만 바꾸는 것**을 권한다.

| 실루엣 | 쓰는 몬스터 |
| --- | --- |
| `bat` | 박쥐 |
| `blob` | 슬라임 · 분열체 · 폭발체 |
| `ghost` | 유령 · 사신 · 주술사 |
| `humanoid` | 좀비 · 괴수 · 사수 · 돌진자 · 방패병 |
| `hound` | 사냥개 |
| `boss` | 제단의 파수꾼 · 역병 군주 · 강철 처형자 · 심연의 왕 |

**등급(정예·희귀)은 추가 그림이 필요 없다.** 코드가 테두리와 크기(×1.24 / ×1.5)로
구분하고 이름표를 붙인다.

## 6. 물리는 법

```js
Sprites.load("atlas.png", {
  bat:   { x: 0, y:   0, w: 32, h: 32, n: 4, fps: 10 },
  slime: { x: 0, y:  32, w: 32, h: 32, n: 4, fps: 8  },
  // ...
  boss1: { x: 0, y: 480, w: 64, h: 64, n: 4, fps: 8, s: 0.438 },
});
```

`art/atlas-frames.json` 이 레퍼런스 아틀라스에 맞는 프레임 정의다. 그대로 붙여 쓰면 된다.

**로드에 실패해도 게임은 그대로 돈다** — `Sprites.draw` 가 `false` 를 돌려주면
호출부가 도형 렌더링으로 폴백한다. 그래서 아트를 한 종류씩 넣어도 되고,
넣다 만 상태로 배포해도 깨지지 않는다.

> 현재 배포본은 **도형 렌더링**을 쓴다. 아티팩트는 외부 파일을 실을 수 없어서,
> 아틀라스를 켜면 아티팩트와 GitHub Pages 가 서로 달라 보이기 때문이다.
> 전면 교체할 때 `Sprites.load` 한 줄을 켜면 된다(PNG 를 data URI 로 넣으면 아티팩트에서도 된다).

## 7. 조달 순서 — 비용 대비 효과 순

1. **실루엣 6종**을 먼저 확보한다. itch.io 의 CC0 실루엣 팩으로 시작해도 된다
2. 반응이 오면 **보스 3종 + 직업 4종**만 전용 아트로 교체한다. 화면에서 가장 오래 보이고
   가장 크게 보이는 것들이다
3. 지형 12종은 **가장 나중**이다. 지금 도형으로도 종류가 구분되고, 크기 편차가
   이미 이정표 역할을 한다

## 8. 레퍼런스 아틀라스 다시 만들기

```sh
node art/make-atlas.js     # art/reference-atlas.png 와 atlas-frames.json 을 다시 뽑는다
```

몬스터를 추가하면 `art/atlas-spec.json` 에 한 줄만 넣으면 된다.
색과 실루엣은 게임 데이터에서 그대로 가져오므로 어긋날 일이 없다.

## 9. 주인공 — 직업 4종 × 동작 4종

몬스터는 단색 실루엣이지만 주인공은 그럴 수 없다. 화면 가운데에서 가장 오래 보이는 것이
한 덩어리 색이면 무엇을 들고 있는지, 지금 무엇을 하고 있는지 읽히지 않는다.
그래서 주인공만 팔레트를 늘렸다.

| 글자 | 쓰임 |
|---|---|
| `A` / `a` | 직업색과 그 그늘 (망토·문양·로브) |
| `S` / `s` | 살 · 살 그늘 |
| `M` / `m` | 강철 · 강철 그늘 |
| `L` / `l` | 가죽 · 가죽 그늘 |
| `W` | 날 끝 광택 · 영창의 빛 |

동작 4종과 각 지속시간(`ACT_DUR` · `CAST_DUR` 은 프레임 4장 ÷ fps 라서 정확히 한 바퀴만 돈다):

| 동작 | fps | 언제 |
|---|---|---|
| `idle` | 6 | 멈춰 있을 때 |
| `walk` | 10 | `player.moving` |
| `attack` | 14 | 무기가 나갈 때(`player.actT`) · 돌진 중 |
| `cast` | 12 | 직업 스킬을 쓸 때(`player.castT`) |

키는 `hero_<직업키>_<동작>` 이다. 오른쪽을 보게만 그리고 왼쪽은 `player.flip` 으로 뒤집는다.
`player.faceX` 는 조준에도 쓰이므로 반전 판정에 쓰지 않는다 — 세로로만 움직이면 0 이 된다.

읽히게 만들려고 실패한 것들:

* 망토를 몸 폭만큼 넓히면 **치마**가 된다 → 왼쪽 뒤로만, 다리는 덮지 않는다
* 무기를 1~2px 로 얇게 그리면 게임 크기에서 **사라진다** → 굵게, 끝에 흰 광택
* 광택을 날 전체에 그으면 날이 **두 배로 두꺼워** 보인다 → 끝 2px 만
* 영창에 두 팔을 올리면 **살색 덩어리**가 된다 → 한 팔만 들고 빛은 무기 앞 한 점에 모은다
* 도끼·지팡이를 수평으로 들면 **걸레·빗자루**다 → 직업별 평상시 각도를 따로 둔다
* `outline()` 은 겉만 잡는다. 허리·다리 사이·투구 틈은 **직접 검은 선**을 그어야 형태가 갈린다

## 10. 이펙트 — 4종 × 속성 6종

타격·폭발·베기·시전이 전부 원과 `shadowBlur` 뿌연 광원이었다. 몬스터와 주인공을
픽셀로 바꾸고 나니 이펙트만 재질이 달라 겉돌았다. 같은 방식으로 픽셀로 찍는다.

| 종류 | 크기 | fps | 언제 |
|---|---|---|---|
| `fx_hit_*` | 32 | 22 | 적이 맞을 때 |
| `fx_boom_*` | 48 | 13 | 처치 · 파동(폭발) · 낙뢰 |
| `fx_slash_*` | 48 | 17 | 근접 베기 (호출부가 각도로 회전) |
| `fx_cast_*` | 32 | 20 | 무기가 나갈 때 |

키는 `fx_<종류>_<속성>` 이고 속성은 물리·화염·냉기·뇌전·신성·피 6종이다.
없는 속성은 `fxKey()` 가 물리로 떨어뜨린다.

이펙트는 몬스터·주인공과 규칙이 다르다.

* **검은 윤곽을 두르지 않는다.** 빛이기 때문이다 — 각 실루엣이 `outline()` 을 부르지 않는다
* **`s`(축소 배수)를 넣지 않는다.** 프레임 크기가 종류마다 달라, `spawnFx` 가
  화면 픽셀 크기를 직접 받고 `px / fr.w` 로 배수를 계산한다. 스펙의 `fx: true` 가 그 표시다
* **색이 `ELEMENTS` 와 다르다.** 가산 합성으로 그리므로 물리(`#d8d8e4`)·신성(`#ffd9a0`) 을
  그대로 쓰면 어두운 배경 위에서 흰 덩어리가 된다. 이펙트에만 채도를 올린 값을 쓴다
  (`#93a6c4` · `#ffc266`). UI·미니맵 색은 건드리지 않는다

혼잡할 때 스스로 줄어든다:

* 적 하나당 `e.flash` 가 남아 있으면 타격 이펙트를 건너뛴다 — 0.12초에 한 번
* 살아 있는 이펙트가 70개를 넘으면 새 타격 이펙트를 포기한다(`fxLive`).
  200마리를 한꺼번에 때리면 불꽃이 서로를 밀어내 죄다 중간에 잘리고 뿌연 덩어리가 된다.
  그럴 바엔 안 그리는 편이 낫다. 치명타만 예외로 항상 그린다
* 배열을 훑어 세면 초당 천 번씩 도는 셈이라 `fxLive` 를 증감으로 관리한다

그리기는 **가산 합성을 루프 바깥에서 한 번만 켠다**. 이펙트마다 `globalCompositeOperation`
을 갈아 끼웠더니 그 전환만으로 프레임이 눈에 띄게 느려졌다.

## 11. 큰 이펙트 — 스프라이트로는 못 그린다

지난 절에서 베기를 `fx_slash` 스프라이트로 그렸다. 그게 틀렸다.

`Sprites.draw` 는 프레임을 확대해서 그린다. 베기의 사거리는 무기마다 다르다 —
쇠사슬 플레일 92, 8레벨 268, 심판의 빛 **520**. 48px 한 장을 520 에 맞추면
**25배 확대**다. 실제로 그렇게 배포했고 화면 1/3을 덮는 계단 모양 덩어리가 나왔다.

기준은 이렇다. **주변 스프라이트가 1:1 로 그려지는데 혼자 몇 배로 확대되면
같은 화면의 픽셀 크기가 어긋난다.** 3배가 한계다.

그래서 큰 이펙트는 화면 픽셀 격자(`PIX = 3`)에 맞춰 직접 찍는다.
길이가 92든 520이든 눈에 보이는 픽셀 크기가 같다.

| 함수 | 쓰는 곳 |
|---|---|
| `pxArc` | 베기 (사거리 300 이하) — 휘두르는 초승달 |
| `pxLance` | 베기 (사거리 300 초과) — 앞으로 내지르는 빛의 창 |
| `pxRing` | 파동 — 퍼져 나가는 고리 |
| (인라인) | 낙뢰 — 꺾인 점 사이를 격자 칸으로 |

`spawnSlash` 에 종류를 따로 두지 않고 **사거리로 갈린다**. 300 을 넘는 베기는
전부 '앞으로 길게 뻗는' 스킬이고, 그걸 부채꼴로 그리면 화면을 덮기 때문이다.

### 두 번 크게 틀렸다

**① 순백을 심지로 썼다.** 이펙트는 가산 합성으로 그린다. `[흰색, 중간, 속성색]`
으로 깔았더니 화염·냉기·신성 파동이 **전부 회색 고리**로 나왔다. 흰색이 겹치는
순간 색이 날아간다. 게다가 물리(`#d8d8e4`)·신성(`#ffd9a0`)은 이미 밝아서
더 밝힐 데도 없다. 그래서 `pxPal` 이 밝기를 보고 갈린다 —
어두운 색은 밝혀서 겉을 만들고, 밝은 색은 **원색을 몸통으로 두고 아래로 깐다**.

**② 칸마다 `fillStyle` 을 갈고 `fillRect` 를 불렀다.** 최악의 프레임에서
**5.8 → 30ms**. 칠할 색은 세 가지뿐이므로 좌표만 쌓아 두었다가 색당 한 번씩
`path` 로 칠한다(`pxPush` / `pxFlush`). 30 → 7.9ms 로 돌아왔다.

계측(적 200 + 긴 베기 3 + 파동 2 + 낙뢰 3 이 매 프레임 살아 있는 인위적 최악):
이전 4.5~7.8ms · 현재 7.3~8.7ms. 일반 전투(적 200, 이펙트 폭주 없음)는
2.2~2.8 vs 2.6~3.4ms 로 겹친다.

## 12. 발사체 — 스프라이트를 쓸 수 없는 이유

발사체는 반지름 5~45 라 스프라이트를 써도 3배 이내다. 규격상으로는 가능하다.
그런데 못 쓴다 — **무기마다 색이 제각각이기 때문이다.**
`spawnProjectile` 이 받는 `color` 는 속성이 아니라 무기별 값이라, 아틀라스에
색깔 수만큼 줄을 넣을 수는 없다. 그래서 여기도 격자로 찍는다.

`pxDisc` 는 **원을 그린 뒤 테두리에 칸을 덧찍지 않는다.** 가로줄로 직접 찍는다 —
안쪽까지 전부 격자에 맞아 진짜 픽셀 원이 되고, 테두리를 따로 도는 비용도 없다.
(테두리를 덧찍는 방식으로 먼저 만들었다가 탄 200발에서 7.6~9.9 → 11.4~11.8ms 로
느려졌다. 가로줄 방식으로 바꾸니 8.2~10.6ms 로 겹친다.)

| 종류 | 그리는 법 |
|---|---|
| 구체 · 불꽃 | `pxDisc` — 겉/속 두 겹. 불꽃은 날아가며 사그라든다 |
| 단검 | 꼭짓점을 직접 돌려 채우고 `pxEdge` 로 테두리 |
| 적 탄 | 붉은 `pxDisc` 위에 제 색 `pxDisc` — 아군 탄과 절대 헷갈리면 안 된다 |

단검만 회전이 필요한데, **회전된 좌표계에서 칸을 찍으면 안 된다.**
격자는 화면 좌표 기준이라 변환 아래에서는 어긋나고 안티에일리어싱이 되돌아온다.
꼭짓점 세 개를 직접 돌려 화면 좌표로 만든 다음 찍는다.

## 13. 바닥 장판

장판은 '점'이 아니라 '면'이다. 발사체처럼 꽉 찬 원으로 그리면 웅덩이가 아니라
색칠한 바닥이 된다. 그래서 셋으로 나눈다.

* **속** — 가로줄로 찍은 옅은 원. 발밑이 어디까지 위험한지 면으로 보인다
* **테두리** — 격자 칸을 **한 칸씩 띄운 점선**. 촘촘히 두르면 장판 하나당 200칸이라
  오래 남는 효과치고 비싸고(장판 6개에 +1.6ms), 점선이 오히려 '여기까지가 구역'으로
  더 잘 읽힌다. 띄우니 +0.6ms 로 내려갔다
* **방울** — 저마다 다른 주기로 떴다 사라지는 칸 16개. 평평한 원에 생기를 준다.
  위치는 `hash2` 로 뽑아 프레임마다 흔들리지 않는다

### 정리 — 무엇을 무엇으로 그리는가

| 크기 | 방법 | 예 |
|---|---|---|
| 고정 크기, 색이 유한 | **스프라이트** (1:1~3배) | 몬스터 · 주인공 · 타격/폭발/시전 |
| 크기가 변하거나 색이 자유 | **격자 렌더** | 베기 · 파동 · 낙뢰 · 발사체 · 장판 · 성역 |

기준은 하나다. **주변 스프라이트가 1:1 인데 혼자 몇 배로 확대되면 어긋난다.**

## 14. 대형 구조물

지형지물(상자·제단·비석)은 한 번 만지고 끝나는 '점'이다.
구조물은 '장소'다 — 켜 두고 그 자리를 지켜야 값을 한다.
크기도 다르다. 반지름 110~180 으로 기존 지형의 두 배 이상이다(폐허가 40~96).

크기가 종류마다 다르고 켜짐/꺼짐으로 색이 바뀌므로 **격자 렌더**다(12·13절의 규칙).

멀리서 실루엣이 구분되어야 갈지 말지를 정할 수 있다. 그래서 윗부분의 형태를 다르게 한다 —
첨탑은 뾰족하게, 샘은 낮고 둥글게, 성채는 톱니, 대장간은 굴뚝.
꺼져 있을 때도 종류색을 조금 섞는다. 전부 같은 회색이면 멀리서 무엇인지 모른다.

큰 면이 비어 있으면 건물이 아니라 판자로 보인다. 그래서 어두운 구멍을 판다 —
첨탑의 띠, 샘의 기둥 사이 그늘, 성채의 화살 구멍과 성문, 대장간의 입구.

## 15. 남은 곳을 전부 — 바닥과 배경

「픽셀이 도입되지 않은 곳이 없게」 전부 옮겼다.

### 바닥은 이제 아틀라스 타일이다

예전에는 체크무늬 사각형 + 머리카락 굵기 격자선이라, 주변이 전부 픽셀인데
바닥만 '비어 있는 판'으로 보였다. 64px 타일 4변종 + 장식 4종(금·자갈·풀·뼈)을
아틀라스에 넣고 좌표 해시로 고른다.

두 번 고쳤다.

* **알갱이 대비를 세웠더니 TV 노이즈가 됐다.** 바닥이 그 위의 몬스터·이펙트와
  싸운다. 두 단계로 줄이고 장식도 전부 어둡게 낮췄다(흰 뼛조각이 아이템처럼 보였다).
* **매 프레임 타일로 화면을 채우니 drawImage 가 275번이었다**(+1.8ms).
  화면보다 한 타일 큰 캔버스에 미리 그려 두고 카메라가 타일 경계를 넘을 때만
  다시 그린다 — 보통 프레임은 blit 한 번이다.

### 지형 12종

`arc` · `stroke` · 다각형 `fill` 을 전부 걷어내고 주사선 방식으로 옮겼다.
색은 세 겹이다 — 겉(어두움) · 몸통 · 윗면(밝음). 위에서 빛이 온다.

실루엣도 손봤다. 덩어리로 그리면 안 되는 것들이 있었다 —
**석벽**은 공이 되고 **폐허**는 웅덩이가 됐다. 벽은 네모나야 벽이고,
폐허는 높이가 들쭉날쭉한 '무너진 벽'이라야 폐허다.
**거대 유해**는 갈비를 점으로 띄엄띄엄 찍어 부스러기로 보였다 — 촘촘히 이었다.

`pxBlob` 도 다시 짰다. 처음엔 '높이마다 폭'으로 계산했는데 `asin` 이 반원만
훑어서 좌우가 늘 대칭인 납작한 타원이 나왔다 — 바위가 아니라 비눗방울이었다.
지금은 꼭짓점을 흔든 다각형을 주사선으로 채운다.

### 그 밖에

그림자 · 보석 · 획득물 · 파티클 · 보스 예고 · 지형지물 셋 · 적 화상 광원.
획득물의 **이모지도 걷어냈다** — 폰트라 픽셀이 아니다. 고기 · 징표 · 약병 · 자석을
도형으로 직접 찍는다.

## 16. 로비 — 시작 화면 · 직업 선택 · 제단

세계는 전부 픽셀로 옮겼는데 로비만 남의 게임처럼 보였다. 두 가지가 원인이었다.

### 이모지

메뉴의 아이콘이 전부 이모지였다. 이모지는 **OS 폰트**라 기기마다 다른 그림이
뜨고, 무엇보다 안티에일리어싱된 벡터라 픽셀과 재질이 어긋난다.
`MENU_ICONS` 에 7×7 비트맵을 문자열로 적어 두고 `drawMenuIcon` 으로 찍는다.
`'.'` 은 빈칸, `2 · 1 · 0` 은 `pxPal` 의 밝은 곳 · 몸통 · 바탕이라
색 하나만 넘기면 3톤이 알아서 나온다.

넣은 것: 구슬 · 문장 · 검 · 마름모(속성) · 별(스킬) · 보석(전리품),
그리고 제단의 여섯 강화(강건함 · 예리함 · 민첩 · 탐욕 · 신념 · 부활).

**5×5 로 줄여 보기도 했는데 실패했다.** 그 크기에서는 검도 별도 마름모도
전부 `+` 로 뭉개져 서로 구분이 안 된다. 판은 7×7 로 두고, 글자 옆에 들어가는
자리는 칸을 2px 로 줄여 쓴다. 세계의 `PIX`(3) 보다 잘아지지만 글자 옆이라
그쪽이 훨씬 잘 읽힌다 — 격자 순수성보다 읽히는 쪽을 택했다.

### 정지 화면

세 화면 모두 불투명하게 덮고 있었다. 지금은 뒤에서 **어트랙트 데모**가
실제 시뮬레이션을 굴리고, 메뉴는 `menuScrim(a)` 로 덮어 가리기만 한다
(시작 .52 · 직업 선택 .68 · 제단 .70). 눌러 주는 띠와 불티도 여기 모아 둬
세 화면이 같은 재질로 보인다.

### 어트랙트 데모가 진짜를 오염시키지 않게

메뉴 뒤에서 진짜 `update()` 를 굴리는 이상, 데모가 남기는 흔적이 기록과
섞이면 안 된다. 조용히 망가지는 종류라 눈으로는 못 잡는다 — `tests/attract.js`
가 최고 기록 · 영혼 · 소리 · 상태 · 흔들림 · 음악 모드를 전부 지킨다.

소리는 `Sfx.muted()` 한 곳에서 막는다. 처음엔 `play()` 안에서만 막았는데,
**레벨업 · 사망 · 각성 팡파레는 `setTimeout` 으로 미룬 소리**라 시뮬레이션이
끝난 뒤에 울린다 — 메뉴에서 갑자기 레벨업 소리가 나는 것이다.
지금은 예약하는 쪽(`Sfx.arp`)에서도 본다.

테스트도 같이 고쳤다. `Sfx.play` 를 감싸 호출을 세면 **막힌 호출까지 세어**
멀쩡한 코드가 실패한다. 오디오 노드가 실제로 만들어졌는지를 세야
`play()` 를 거치지 않는 경로가 생겨도 걸린다.

## 17. 직업 카드 — 표를 걷어내고 무기를 돌린다

카드는 수치 표였다. 자세 · 무기 · 속성 · 자원 · 스킬 · 전리품 여섯 줄.
고르는 사람이 알고 싶은 건 그 표가 아니라 둘이다 —
**무엇을 들고 어떻게 싸우는가**, 그리고 **다른 직업과 견줘 어디가 세고 어디가 약한가**.

### 무기 무대

카드 안에 236×104 짜리 작은 무대를 놓고 시작 무기를 실제로 돌린다.
바닥은 `Sprites.drawTile("floor", …)` — 게임의 그 타일이다. 적도 게임의 스프라이트,
타격 이펙트도 `fxKey("hit", element)` 로 게임이 쓰는 그 프레임이다.
**여기서만 따로 그리면 미리보기가 아니라 거짓말이 된다.**

무기도 게임의 픽셀 함수를 그대로 부른다.

| 직업 | 무기 | 그리는 법 |
|---|---|---|
| 성기사 | 성역 | `pxRing` — 상시 결계가 주기마다 밝아지고, 그때 안에 든 적이 탄다 |
| 전사 | 쇠사슬 플레일 | `pxArc` — 부채꼴 참격. 맞는 판정도 사거리+각도로 게임과 같다 |
| 추적자 | 투척 단검 | 꼭짓점을 직접 돌린 사각형 + `pxEdge` — 관통하므로 첫 적을 지나 계속 난다 |
| 마법사 | 마법 화살 | `pxDisc` — 유도탄이라 곧게 가지 않고 옆으로 부풀었다 붙는다 |

주인공 초상은 뺐다. 무대 안에서 실제로 싸우므로 따로 세워 둘 이유가 없다.
카드마다 주기 위상을 어긋나게 해 네 장이 한꺼번에 번쩍이지 않게 했다.

**적을 작게 잡았다가 한 번 고쳤다.** 반지름 10~13 으로 두니 좀비가 사람이 아니라
덤불로 보였다. 15/13/12 로 키우니 실루엣이 산다.
성역은 결계라 적이 둘러싸야 하는데, 고리 반지름 58 은 무대 높이(104)를 넘어
위아래가 잘렸다 — 46 으로 줄이고 적을 고리 위에 앉혔다.

### 견줌 막대

생존 · 공격 · 기동 · 범위 · 전리품 다섯 축. 값은 `mods` 에서 뽑는다
(생존 = 체력 ÷ 방어 × 재생, 공격 = 피해 ÷ 쿨다운 × 치명).

**0 부터 그리면 안 된다.** 공격이 1.0~1.2 라 네 막대가 똑같아 보이고,
그러면 고르는 데 아무 도움이 안 된다. 네 직업의 최소~최대를 막대 폭에 펼친다.
바닥은 .18 로 띄운다 — 가장 낮은 것이 빈 칸이면 '없다'로 읽힌다.
절대값이 아니므로 카드 아래에 그렇게 적어 둔다.

### 조용히 죽는 것을 막는 테스트

무대는 조용히 죽는다. 위상 계산이 어긋나 이펙트 구간을 영영 못 만나거나
스프라이트 키가 바뀌어 적이 안 나와도, 화면은 멀쩡한 바닥 타일을 보여준다.
눈으로는 '좀 심심하네' 정도로만 보이고 아무도 버그라고 부르지 않는다.

`tests/class-cards.js` 가 한 주기를 240 등분해 훑으며,
직업마다 제 무기 함수가 불렸는지 · 타격 이펙트가 떴는지 · 적과 주인공이 그려졌는지 ·
캔버스 상태(알파 · 합성 모드)를 흘리지 않는지, 그리고 막대가 축마다 실제로 갈리는지 본다.

## 18. 제단과 재시작

### 제단에 제단이 없었다

「영혼의 제단」이라면서 화면에 제단이 없었다. 강화 카드 여섯 장이 허공에 떠 있고
그 아래는 빈 판이었다. 돌 받침 세 계단 · 홈을 판 기둥 · 대접, 그 위에 뜬 영혼 구슬을
격자로 찍는다. 모은 영혼도 별도의 숫자 줄이 아니라 이 제단이 들고 있게 했다 —
그래야 장식이 아니라 물건이 된다.

돌색은 **`pxPal` 에 맡기지 않는다.** 자주색 계열은 밝기 판정(`lum > .7`)에 걸려
세 톤이 전부 밝은 쪽으로 몰리고, 제단이 돌이 아니라 젖은 비누처럼 보였다.
`["#7a7392", "#4a4460", "#2b2540"]` 로 직접 잡았다 — 윗면 · 앞면 · 그늘.

부스러기는 대접에서 구슬까지만 띄웠더니 거리가 24px 뿐이라 아무것도 안 보였다.
기둥 전체를 쓰고, 오를수록 가운데로 모이게 해 구슬이 빨아들이는 것으로 읽히게 했다.
구슬도 한 번 올렸다 — 후광(반지름 40)이 대접을 덮고 있었다.

레벨 눈금의 `roundRect` 도 `pxR` 로 바꿨다. 여기만 둥근 모서리를 쓰면 재질이 어긋난다.

### 길이 끊겨 있던 곳

화면은 멀쩡한데 길이 끊긴 버그는 눈으로 안 잡힌다. 둘 있었다.

**어트랙트 데모가 전역 `selectedClass` 를 덮어썼다.** 타이틀에서 성기사를 골라 놓아도
데모가 새 판을 깔 때마다 고른 직업이 제멋대로 바뀌었다 — 카드 강조도 저 혼자 옮겨 다녔다.
`Game.reset(clsIdx)` 로 직업을 인자로 받게 하고, 데모는 제 직업을 따로 들고 다닌다.
「R 로 같은 직업 즉시 재시작」은 이걸 고치기 전에는 말이 안 되는 기능이었다.

**판이 끝난 뒤 갈 곳이 '다시 시작' 하나뿐이었다.** 죽어서 영혼이 들어왔는데 제단으로
갈 길이 없어 새로고침 말고는 방법이 없었다. 끝 화면에 갈래를 냈다 —
`SPACE`·`R` 같은 직업으로 즉시 · `ESC` 직업 다시 고르기 · `TAB` 영혼의 제단.
제단에 들어오는 네 길이 전부 `introFrom` 을 남기게 해서 `ESC` 가 제자리로 돌아간다
(전에는 세 곳이 안 남겨 이전 값이 그대로 쓰였다).

일시정지에도 `R` 을 넣되 **두 번 눌러야** 판을 버린다. 한 번에 날아가면 안 된다.

### 테스트

`tests/menu-flow.js` — 데모가 내 선택을 건드리지 않는지(그러면서 데모 자신은 여러
직업을 도는지) · 끝 화면의 세 갈래 · R 재시작이 같은 직업인지 · 포기가 두 번인지 ·
제단 구입이 키와 클릭에서 같은 길을 타는지 · 제단에서 들어온 곳으로 돌아가는지.

고치기 전 코드로 되돌려 돌려 봐서 실제로 잡히는 것을 확인했다 —
4개 항목이 실패하고 `내 선택 2/1` 로 직업이 밀려 있었다.

## 19. 영혼 경제 — 재고, 그리고 보이게 만들기

### 한 판이면 제단을 통째로 샀다

봇으로 판을 끝까지 굴려 재 봤다. 옛 정산식은 이랬다.

```
영혼 = 처치 ÷ 8  +  시간 ÷ 10  +  (클리어면 150)
```

문제는 **이 게임의 처치 수가 시간에 대해 폭발한다**는 것이다. 성기사 봇이 7분에
75,098마리, 8분에 94,669마리를 잡았다. 처치를 그대로 8로 나누니 한 판에
**9,429영혼**이 들어왔다. 제단 전체가 6,240이었다 — 잘한 판 하나로 전부 사고도 남는다.

화면에는 아무 이상이 없다. 숫자로만 잡힌다.

### 고친 식

```
영혼 = 시간 ÷ 6  +  60 × √(처치 ÷ 1000)  +  (클리어면 200)
```

처치는 제곱근으로 눌러 담는다 — 1,000마리 60 · 10,000마리 190 · 75,000마리 520.
잘한 판이 더 주긴 하되 **배수로 벌어지지는 않는다.** 주 수입은 '얼마나 버텼는가'로
옮겼다. 15분이라는 상한이 있어 폭발할 수 없는 값이다.

값도 다시 잡았다(전부 11,570). 계측된 판별 지급액과 제단 전체 대비 비율:

| 판 | 영혼 | 제단 대비 |
|---|---|---|
| 25초에 죽음 | 9 | 0.1% |
| 1분 35초 · 320마리 | 48 | 0.4% |
| 5분 10초 · 19,000마리 | 312 | 2.7% |
| 8분 05초 · 94,669마리 | 663 | 5.7% |
| 15분 클리어 · 200,000마리 | 1,198 | 10.4% |

첫 칸(90)은 첫 판이나 두 번째 판에 닿고, 전부 채우려면 서른다섯 판 안팎이 든다.

### 보이게 만들기

숫자를 고쳤으면 그 숫자가 읽혀야 한다.

**끝 화면** — 합계만 던지면 다음 판에 무엇을 더 해야 많이 버는지 알 수가 없다.
`버팀 8:05 → +80 · 처치 94,669 → +583` 로 내역을 편다. 버틴 시간이 주 수입이라는
설계가 여기서 읽힌다.

**제단 카드** — 「최대 체력 +8%」만 적어 두면 지금 내가 몇 %인지, 하나 더 사면
몇 %가 되는지 머리로 곱해야 한다. `최대 체력 +16% → +24%` 로 지금 값과 다음 값을
나란히 놓는다. `desc` 에 같은 숫자를 또 적어 두면 한쪽만 고칠 때 어긋나므로,
`per · step · unit` 에서 글을 만든다.

카드 아래에는 **모으는 진행 막대**를 깔았다(보유 ÷ 값). 살 수 있으면 금색으로 꽉 차고,
아니면 `737 더` 가 붙는다. '얼마나 더 모아야 하나'가 숫자 뺄셈이 아니라 눈에 보여야
제단에 다시 올 이유가 생긴다. 못 사는 칸을 예전처럼 알파 .45 로 눌러 버리면
정작 모으는 동안 볼 것이 안 보여서 .72 로 올렸다.

**제단 구슬이 곳간이다** — 보유 영혼에 따라 구슬과 후광이 자란다(4,000에서 최대).
숫자를 안 읽어도 얼마나 모았는지 보인다. 그 아래에 `지난 판 +663` 도 적는다.
이 값은 `Game.lastEarned` 에 따로 둔다 — 제단에 들어서는 순간 어트랙트 데모가
`Game.reset()` 을 불러 `soulsEarned` 를 지워 버리기 때문이다.

### 테스트

`tests/souls.js` — 처치가 두 배여도 영혼이 두 배가 되지 않는가(제곱근 배수 1.42) ·
최고의 판도 제단 절반을 못 사는가 · 그러면서 첫 칸은 두 판 안에 닿는가 ·
값이 레벨마다 오르는가 · 총액이 제자리인가 · 구입이 표시된 값만큼만 깎는가 ·
내역의 합이 지급액과 같은가.

옛 식으로 되돌려 돌려 봐서 실제로 잡히는 것을 확인했다 — 4개 항목이 실패하고
처치 배수가 정확히 2.00 으로 찍혔다.

## 20. 모바일 — 반쪽만 돌아가던 것

### 재 보니 두 가지가 막혀 있었다

**터치로는 직업 스킬과 아이템을 쓸 수 없었다.** 터치 이벤트는 가상 조이스틱(이동)만
처리했고, 스킬은 `SPACE`·`Shift`·우클릭, 아이템은 `Q`·`E` — 전부 키보드와 마우스였다.
폰으로 열면 직업의 절반과 소모품이 통째로 잠겨 있었다.

**세로로 들면 화면의 1/4 이 됐다.** 논리 해상도를 1280×720 으로 고정하고
`min(vw/W, vh/H)` 로 맞췄더니 390×844 짜리 폰에서 **390×219** 짜리 띠가 나왔다.

### 논리 해상도가 화면 비율을 따라간다

| 뷰포트 | 논리 해상도 |
|---|---|
| 390×844 (폰 세로) | 520×1126 |
| 844×390 (폰 가로) | 1410×652 |
| 820×1180 (태블릿 세로) | 520×748 |
| 1440×900 (노트북) | 1212×758 |
| 2560×1080 (와이드) | 1480×624 |

가로 화면은 **보이는 넓이**(1280×720)를 지킨다 — 16:10 이든 21:9 든 세계가 같은 양만큼
보여야 공평하다. 세로 화면은 그럴 수 없다. 넓이를 지키면 논리 폭이 650을 넘고,
그러면 390px 짜리 폰에서 13px 글자가 7px 로 찍혀 읽히지 않는다.
그래서 폭을 520 으로 먼저 정하고 높이를 늘린다 — **대신 세로로 들면 세계가 덜 보인다.
그건 화면 모양의 대가지 버그가 아니다.**

### 메뉴가 접힌다

- 직업 선택: 4열 → **2×2** (1,126px 이 필요해 세로 화면에서는 가운데 두 장만 보였다)
- 제단: 3열 → **1열**, 제단 돌은 배율로 줄여 세운다
- 레벨업 · 전직: 카드를 **세로로 쌓고 통째로 줄인다**. 내용이 빽빽해 다시 짜는 대신
  좌표계를 한 번 옮기는 쪽을 골랐다 — 마우스도 같은 계로 옮겨 판정한다
- 시작 화면: 버튼을 위아래로 쌓고 규칙을 두 줄로
- 자리가 없으면 참고 정보(조합 칩)를 접는다 — 가로로 든 폰은 높이가 652 뿐이다

### 터치 조작

오른쪽 아래에 스킬 · 아이템 버튼을 놓았다. 스킬 버튼은 **자원이 차는 만큼 안쪽이 차서**
언제 쓸 수 있는지 버튼만 봐도 안다. 조이스틱도 눈에 보이게 그렸다 — 여태 '보이지 않는'
물건이라 어디를 눌러야 하는지 알 수 없었다.

손가락은 여러 개다. `changedTouches` 를 하나만 보면 조이스틱과 버튼을 동시에 못 쓴다 —
식별자로 조이스틱 손가락을 따로 추적한다. 터치가 확인된 뒤에는 미니맵을 오른쪽 위로
올리고(버튼 자리와 겹친다) 아이템 칸을 왼쪽 아래로 옮긴다.

### 이번에도 조용히 죽을 뻔했다

카드 높이를 검사하는 코드에서 **아직 선언되지 않은 변수를 읽어(TDZ)** 가로로 든 폰에서
직업 선택 화면이 통째로 빈 화면이 됐다. 문법도 통과하고 다른 테스트도 전부 통과했다.
페이지 예외를 아무도 안 봤기 때문이다.

`tests/layout.js` 는 여섯 가지 화면 크기 × 일곱 화면을 돌면서
`panel()` 과 `fillText()` 를 감싸 **이번 프레임에 어디에 그렸는지**를 모으고,
전부 캔버스 안에 있는지 · 화면이 비어 있지 않은지 · 페이지 예외가 없는지 본다.
화면마다 좌표를 적지 않으므로 배치를 바꿔도 안 깨진다.
터치 버튼은 실제로 탭을 보내 스킬이 나갔는지 확인한다.

그 테스트가 처음 돌 때 자기 자신의 계측 오류도 두 개 냈다 — `panel` 에 좌표 변환을
안 먹여 멀쩡한 카드를 화면 밖이라 했고, 글자 기준선을 middle 로만 가정해 HUD 를
오탐했다. **재는 도구부터 고치고 나서** 남은 셋이 진짜였다.

### 덧붙여

`tests/regress-levelup-spam.js` 가 임시 폴더의 계측 스크립트에서 봇 소스를 읽고 있었다.
그 파일을 덮어쓴 날 게임은 멀쩡한데 테스트만 죽었다 — 봇을 `tests/bot.js` 로 들여왔다.
그러면서 이 테스트가 22초에 죽어 레벨 2 에서 끝나고 있던 것도 고쳤다.
'후반에 고를 게 없어지는가'를 보는 테스트가 후반에 닿지 못하고 있었다.
체력을 주어 15분을 완주하게 하니 레벨 24 · 레벨업 창 23회 · 회복 3장 0회가 나온다.

메뉴를 전부 픽셀로 옮기고도 **화면에 그려지는 이모지가 열다섯 곳** 남아 있었다.

`🛡 방벽` · `☠ 처치수` · `🔯 징표` · `🧪 광란` · `🔰 수호` · `❗ 미션` ·

무기 8 · 능력 9 · 소모품 5 · 속성 6 · 지형지물 3 · 구조물 4.

## 22. 설정 — 여태 M 하나뿐이었다

설정이라고는 `M`(소리 전체 끄기) 하나였다. 음악만 끄고 효과음은 듣는다든가,
화면 흔들림이 불편하다든가, 피해 숫자가 어지럽다든가 — 어느 것도 손댈 수가 없었다.

| 항목 | 값 |
|---|---|
| 효과음 | 0~100% (4단계) |
| 음악 | 0~100% (4단계) |
| 화면 흔들림 | 끔 · 절반 · 기본 |
| 몬스터 이름표 | 끔 · 켬 |
| 피해 숫자 | 끔 · 켬 |
| 기록 지우기 | 두 번 눌러야 실행 |

### 슬라이더 대신 칸

값은 **칸**으로 보여준다. 슬라이더는 터치에서 잡기 어렵고 이 정도 항목에는 과하다.
칸을 직접 눌러도 되고 방향키로 옮겨도 된다 — 마우스 · 터치 · 키보드가 같은 것을 본다.

음량은 **막대**(찬 만큼 켜진다), 나머지는 **라디오**(고른 것 하나만 켜진다)로 나눴다.
처음엔 같은 규칙으로 그렸는데 음량 50% 인데 다섯 칸 중 셋이 켜져 60% 로 보였다 —
`0` 도 하나의 칸을 차지하고 있었기 때문이다. 음량은 0 을 칸에서 뺐다.

### 흔들림은 '읽는 곳'에서 곱한다

`cam.shake` 에 값을 넣는 곳이 **스물일곱 군데**다. 거기마다 배수를 곱하면
한 곳만 빠뜨려도 조용히 어긋난다. 화면을 실제로 옮기는 `frame()` 한 곳에서 곱한다.

### 갈 길이 없으면 설정이 아니다

`O` 키만으로 열게 두면 폰에서는 못 연다. 그래서 —
시작 화면에 **설정 버튼**, 전투 중에는 왼쪽 아래 **일시정지 버튼**(폰에는 `ESC` 가 없다),
일시정지 화면의 세 줄(계속 · 설정 · 포기하고 다시)을 전부 **누를 수 있게** 했다.
단축키는 각 줄 오른쪽에 같이 적는다.

### 조용히 죽기 쉬운 것

설정은 값이 바뀌고 저장도 되는데 정작 **쓰는 쪽이 안 보고 있으면** 화면에 아무 이상이
없다. 사용자만 '왜 안 되지' 한다. 그래서 `tests/options.js` 는 값이 아니라 **결과**를 잰다 —
소리가 실제로 났는지(오디오 노드 생성), 화면이 실제로 옮겨졌는지, 이름표와 숫자가
실제로 안 뜨는지, 다시 읽었을 때 그대로인지, 기록 지우기가 한 번에는 안 지워지는지.

여기서도 계측을 한 번 틀렸다. 흔들림을 재려고 `ctx.translate` 를 전부 셌더니
월드를 화면으로 옮기는 호출이 1,160px 로 잡혀 **꺼도 켠 것과 같은 값**이 나왔다.
한 프레임의 *첫* `translate` 만이 흔들림이다.
